# Документация проекта: старт, итог сессии, подпроект, аудит, сжатие, исправление

Документация тут - не отчёт для людей, а рабочий контекст: Claude читает её в начале сессии и
дописывает в конце. Отсюда три требования: короткая (бюджеты размера), проверяемая (якоря и
метки источника), с одним местом для каждого вида знания. Стиль: простой русский, короткий
дефис `-`, даты `14.08.2026`.

Полные правила - `references/rules.md`. Скелеты - `references/skeletons/`. Доведение
существующей документации - `references/migration.md`. Сжатие и архив -
`references/compaction.md`. Скрипты - `scripts/` (установлены в
`~/.claude/skills/project-docs/scripts/`).

## Шаг 0. Проверка версии

Перед работой проверь, что скилл свежий:

    REPO=$(git -C ~/.claude/skills/project-docs rev-parse --show-toplevel)
    git -C "$REPO" fetch --quiet
    git -C "$REPO" status -sb

- Ветка отстаёт и нет локальных изменений → `git -C "$REPO" pull --ff-only`, перечитай
  этот SKILL.md и продолжай по новой версии. Скажи пользователю одной строкой, что обновился.
- Есть локальные изменения или ветки разошлись → не обновляй, скажи пользователю, что именно
  не так, и продолжай на текущей версии.
- Нет сети или репозитория → продолжай на текущей версии и скажи об этом.

## Режим - по аргументу или по фразе

| Аргумент / фраза | Режим | Когда |
|---|---|---|
| «старт», «заведи документацию», «доведи до скилла» | **Старт** | новый проект, или проект со старой раскладкой |
| «итог сессии», «запиши итог», «зафиксируй в журнале» | **Итог** | конец сессии или большого куска работы |
| «подпроект <имя>», «выдели подпроект» | **Подпроект** | у части проекта свои задачи и свой контур |
| «аудит», «проверь документацию» | **Аудит** | раз в неделю или перед сжатием |
| «сжатие», «документы разрослись», «ротация» | **Сжатие** | линтер ругается на бюджеты; в начале месяца |
| «исправить», «это неверно, поправь» | **Исправление** | утверждение в документах оказалось ложным |

Чекпойнты по задачам спринта («статус», «где мы по спринту», «итог спринта», «закрой спринт»)
и строки `[СОСТОЯНИЕ]` - скилл `sprint-planning`. Итог спринта в журнал пишет только он.

## Раскладка

```
<корень>/
  CLAUDE.md             точка входа: проект в трёх абзацах, таблица «нужно - файл», местные правила
  docs/
    CONTEXT.md          как всё устроено сейчас; §«Чего не умеет и что не сработало» обязателен
    CHANGELOG.md        что делали и почему, свежее сверху; каждая запись кончается блоком «Где мы»
    TASKS.md            открытые вопросы, блокеры, раздел «Активный спринт» с постоянным номером
    CONVENTIONS.md      правила команды; таблицы: местные метки, вне раскладки, внешние корни
    changelog/          журнал прошлых месяцев: 2026-09.md - не правится
    notes/              разовые документы с датой: разборы, спецификации, ревью - не правятся
    howto/              рецепты «как сделать X»: прогон, выкат, трейсы
    projects/<имя>/     подпроект: CONTEXT.md, TASKS.md, при необходимости notes/
  ARCHIVE/
    README.md           опись: что лежит, откуда, карта переездов
    <ГГГГ-ММ-ДД>/       оригиналы до переезда или сжатия
```

Каталоги `changelog/`, `notes/`, `howto/` создаются при первой надобности. Отдельного файла
«где мы» нет: состояние живёт в блоке «Где мы» в конце каждой записи журнала, по абзацу на
поток. Почему - `references/rules.md §4`.

## Поводы: что случилось - куда писать

| Случилось | Куда |
|---|---|
| Сессия заканчивается или сделан большой кусок | запись в `CHANGELOG.md` с блоком «Где мы» |
| Закрыли вопрос | `[ОТВЕТ <дата>]` в `TASKS.md`, разбор - в журнал |
| Появился вопрос без ответа | `[ДООПРОС]` в `TASKS.md` с владельцем и способом закрыть |
| Изменилось устройство системы | правка раздела `CONTEXT.md`; причина одной строкой: «почему так: журнал <дата>» |
| Влит МР, выкат, замер | строка `[ФАКТ]` в записи журнала с номером и якорем |
| Отвергли путь, наступили на грабли | `[ОТВЕРГНУТО <дата>]` / `[ВАЖНО]` в журнале **и** строка в `CONTEXT.md` «Чего не умеет и что не сработало» |
| Утверждение оказалось ложным | режим «исправление» |
| Разбор длиннее 40 строк | `notes/<дата>-<тема>.md`, в журнале ссылка |
| Повторяемый рецепт | `howto/<тема>.md`, строка в таблице `CLAUDE.md` |

## Как читать документы в начале сессии

1. `CLAUDE.md` целиком.
2. `CHANGELOG.md`: оглавление `grep -n "^## "`, две-три верхние записи целиком. Состояние
   своего потока - последний абзац `- **<поток>.**` в блоке «Где мы»:
   `grep -n "^- \*\*thread\.\*\*" docs/CHANGELOG.md | head -1`.
3. `CONTEXT.md`: оглавление `grep -n "^#"`, нужный раздел по смещению, §«Чего не умеет» всегда.
4. `TASKS.md`: «Блокеры», «Активный спринт» и вопрос, который касается задачи.
5. Старое - поиском по `docs/CHANGELOG.md`, `docs/changelog/`, `docs/notes/`, не чтением
   подряд. Файл длиннее 500 строк целиком не читать.

## Бюджеты размера

Считаются непустые строки. Линтер: превышение в файлах раскладки - ошибка, в остальных -
предупреждение.

| Файл | Строк | При превышении |
|---|---|---|
| `CLAUDE.md` | 80 | местные правила - в `CONVENTIONS.md`, по строке на каталог, не на файл |
| `CONTEXT.md` | 800 | процедуры - в `howto/`, история - в журнал, разборы - в `notes/` |
| `TASKS.md` | 500 | свернуть закрытые вопросы |
| `CONVENTIONS.md` | 400 | рецепты - в `howto/` |
| `CHANGELOG.md` | 2000 | ротация прошлого месяца в `changelog/<год>-<месяц>.md` |
| запись журнала | 40 | тело - в `notes/`, в записи выжимка и ссылка |
| `projects/*/CONTEXT.md`, `TASKS.md` | 600, 400 | как у общих |
| прочие `.md` в `docs/` | 500 | предупреждение; `notes/` и `changelog/` не считаются |

## Режим «Старт»

Два случая. **Новый проект** - раскладка по скелетам. **Доведение** - `docs/` уже есть по
этой раскладке или по старому `DOC_TEMPLATE.md`: завести только недостающее, старые разделы
«Состояние на <дату>» превратить в первую запись журнала с «Где мы», метки перевести по
таблице, `DOC_TEMPLATE.md` заменить заглушкой. Порядок доведения - `references/migration.md`.

### Что собрать
1. Что уже есть: `CLAUDE.md`, `docs/`, старые документы в корне, разделы «Состояние на».
2. Что за проект: из `README`, кода, слов пользователя. Чего не хватает - спросить одним списком.
3. Правила команды: формат задач, веток, коммитов, кто жмёт кнопки. Потоки работы (будущие
   `projects/<имя>` и «общее»).

### Что выдать
План одним экраном: какие файлы создать или дополнить, что в них попадёт, что куда переедет
(с числом строк). Старые документы не удаляются - порядок в `references/compaction.md`.

### Что записать - только по «делай»
1. `docs/CONTEXT.md`, `CHANGELOG.md`, `TASKS.md`, `CONVENTIONS.md` по скелетам. Пустыми не
   оставлять: шапка, дата, хотя бы один заполненный раздел.
2. `CLAUDE.md` по скелету: три абзаца, таблица «нужно - файл», блок «Правила этих документов»
   на пять строк, ссылка на скилл и его репозиторий. Полные правила не копировать.
3. `CONVENTIONS.md §«Документы»`: номер раздела «Активный спринт», таблицы «Местные метки»,
   «Вне раскладки», «Внешние корни» - могут быть пустыми, но должны быть.
4. Первая запись журнала с блоком «Где мы» по каждому потоку.
5. Старые документы - по `references/compaction.md`: `archive_copy.py`, опись, карта переездов.

## Режим «Итог»

Цель: следующая сессия начинает с верхней записи журнала и не теряет ничего из этой.

### Что собрать
0. Перечитать с диска верхние две записи журнала и блок «Где мы» своего потока - чтобы не
   дублировать и не затереть чужое: в проекте могут работать несколько сессий.
1. Факты из инструментов, не из памяти: `git log --since`, список МР, выкаты, замеры,
   прочитанное в коде - с якорями. Начало длинной сессии уже могло быть сжато.
2. Решения и отвергнутые пути с причиной. Грабли.
3. Вопросы: какие закрыли (чем), какие появились (кто владелец).
4. Что изменилось в устройстве системы - затронутые разделы `CONTEXT.md`.
5. Утверждения, которые оказались ложными.
6. Для блока «Где мы» по каждому затронутому потоку: в работе, блокер или ждём, следующий
   шаг, ветки и МР в полёте, не делать.

### Что записать - сразу, дифф показать после
Запись журнала и `[ОТВЕТ]`/`[ДООПРОС]` в `TASKS.md` - дописывание, оно обратимо, пишется без
подтверждения. Подтверждения ждут: правка `CONTEXT.md`, `[ИСПРАВЛЕНО]`, закрытие вопроса с
чужим владельцем.
1. Запись в `CHANGELOG.md` сразу под шапкой через `Edit`, формат из скелета, до 40 строк.
   Заголовок `## ДД.ММ.ГГГГ - <что>`; несколько записей за день допустимы, различаются темой.
   Разбор длиннее - `notes/<дата>-<тема>.md`, в записи две строки и ссылка.
2. Блок «Где мы» в конце записи: `- **<поток>.**` по каждому затронутому потоку. Потоки -
   имена папок `projects/` и `общее`. Не затронутые потоки не повторять: их состояние ищется
   по прошлым записям.
3. `TASKS.md`: закрытым вопросам - `[ОТВЕТ <дата>]` в заголовке и ответ в две-три строки со
   ссылкой на дату журнала, номер раздела не меняется; новым - `[ДООПРОС]` с владельцем и
   способом закрыть, в конец со следующим номером.
4. `CONTEXT.md`: только раздел, где изменилось устройство. «Как было» не оставлять - это
   журнал. Причина - одной строкой: «почему так: журнал <дата>». Отвергнутое и грабли -
   строкой в §«Чего не умеет и что не сработало».
5. Ложные утверждения - по режиму «исправление».
6. Строки `[СОСТОЯНИЕ]` и раздел «Активный спринт» не трогать - это `sprint-planning`.

### Правила режима
- В «Где мы» - только то, что есть в теле этой записи или в журнале. План («поставить тег на
  `90926ba`») не записывать как сделанное; не подтверждено - `[ДООПРОС]` или `[СЛОВА ...]`.
- Итог после каждого большого куска, а не раз в конце: сжатый контекст сессии факты не вернёт.
- Без якоря - `[ВЫВОД]` или `[СЛОВА]`, не `[ФАКТ]`. «Работали над» не писать - что получилось.
- Кусков кода и логов в журнале нет: путь или якорь.

## Режим «Подпроект <имя>»

Повод: у части проекта свои задачи, свой контур, свои люди. Упомянут в двух строках - ещё не
повод, живёт разделом в `CONTEXT.md`.

1. Папка `docs/projects/<имя-латиницей>/` с `CONTEXT.md` и `TASKS.md` по скелетам подпроекта.
   В шапке `CONTEXT.md` строка «Общая картина - в `../../CONTEXT.md`». Общее не пересказывать.
2. По строке на файл в таблице `CLAUDE.md`. Строка в таблице `TASKS.md` «куда смотреть».
3. Из общего `CONTEXT.md` перенести только то, что касается одного подпроекта; на месте - две
   строки и ссылка. Дубль живёт до первой правки, потом это два разных утверждения.
4. Запись в журнал с «Где мы» нового потока: подпроект выделен, причина, что откуда переехало.

Показать план, записать по «делай».

## Режим «Аудит»

1. Линтер: `python3 ~/.claude/skills/project-docs/scripts/doc_lint.py <корень> --summary`.
   Ошибки (код выхода 1): тире, метки вне набора, метки без обязательной даты, битые ссылки
   на файлы и разделы, бюджеты раскладки, «Состояние на» вне журнала, нет обязательного файла.
   Предупреждения: относительные даты, записи без «Где мы», потоки без свежего «Где мы»,
   нарушение формата и порядка заголовков журнала, записи старше месяца (пора ротировать),
   похожее на секреты и почты, бюджеты прочих файлов. `changelog/` и `notes/` - только ссылки
   и секреты. Исключения - таблица «Вне раскладки» в `CONVENTIONS.md`.
2. Смысловой чек-лист руками - `references/rules.md §9`, пункты, которые линтер не покрывает:
   история и процедуры в `CONTEXT.md`, дубли фактов, якоря на живой код, `[ДООПРОС]` с
   владельцем, персональные данные, `ARCHIVE/` описан.
3. Выдать таблицу: находка, файл и строка, предлагаемая правка. Мелкое (тире, даты) - пачкой
   по «делай». Крупное (дубли, история в контексте) - режимом «сжатие».

## Режим «Сжатие»

Ничего не теряем, но не держим в рабочем контексте то, что нужно раз в квартал. Текст
переезжает дословно, со ссылкой на новое место. Переписывать смысл старых записей нельзя.
Полный порядок - `references/compaction.md`.

### Что выдать
План таблицей «что - откуда - куда - строк», итог «было N, станет M», и 8-10 контрольных
вопросов по переносимому материалу. Операции, в этом порядке:
1. Из уходящих записей журнала - `[ОТВЕРГНУТО]`, `[ВАЖНО]`, `[ПРАВИЛО]`, `[РЕШЕНИЕ]`
   (`compact_changelog.py <корень> --rules` печатает кандидатов с датами) строкой в
   `CONTEXT.md §«Чего не умеет и что не сработало»`. Иначе через месяц это предложат снова.
2. Ротация и выжимки - `compact_changelog.py <корень>` (план), потом `--apply`: записи прошлых
   месяцев в `changelog/<год>-<месяц>.md` как есть; оставшиеся длиннее 40 строк - целиком в
   `notes/`, в журнале выжимка из блоков оригинала дословно и ссылка. Две-три выжимки проверить глазами.
3. `TASKS.md`: закрытые вопросы - до трёх строк на своём номере, полный текст в `notes/`, если
   разбора в журнале нет; прошлые спринты - в `notes/`, заглушка; «Состояние на» - сверить с
   журналом, нет там - в `notes/`, есть - заглушка.
4. `CONTEXT.md` и `CONVENTIONS.md`: «как было» и «решение от <даты>» - одной записью сверху
   журнала с датой сжатия и подпунктами с исходными датами; процедуры с командами - в `howto/`.
5. Подпроекты - то же, по одному за раз.

### Что записать - только по «делай»
`archive_copy.py` → правка → опись и карта переездов в `ARCHIVE/README.md` → строки в
`CLAUDE.md` → запись в журнал с числами строк → контрольные вопросы свежему субагенту, который
видит только `CLAUDE.md` и `docs/`. Не ответил - сжатие потеряло, вернуть из архива.

## Режим «Исправление»

Тихо переписать нельзя: кто уже прочитал старую версию, останется при ней.

1. `grep -rn` по характерным словам: `CLAUDE.md`, `docs/` целиком, `ARCHIVE/` не трогать.
2. Проверить верное утверждение тем способом, каким его можно опровергнуть, и записать чем.
3. В живых файлах (`CONTEXT`, `TASKS`, `CONVENTIONS`, `howto/`, `CLAUDE.md`) - на месте старого:
   ```
   `[ИСПРАВЛЕНО 14.08.2026]` Раньше здесь стояло, что <неверно>. Это оказалось неверно:
   <как на самом деле>. Проверено <чем>.
   ```
4. Старые записи журнала, `changelog/`, `notes/` не правятся: новая запись журнала с
   `[ИСПРАВЛЕНО <дата>]` перечисляет, где стояло, и чем проверено.

Показать список мест и текст, записать по «делай».

## Правка скилла

Если пользователь просит изменить скилл или по ходу работы стало ясно, что инструкция
неверна:
1. Правь файл в репозитории (`git -C ~/.claude/skills/project-docs rev-parse --show-toplevel`),
   а не копию.
2. Покажи пользователю, что меняется (diff), и дождись «да».
3. Найденную ошибку допиши строкой в «Грабли», чтобы она не повторилась.
4. Закоммить одной строкой в формате, принятом в репозитории (см. его README), и запушь.
5. Пуш отклонён → `git pull --rebase`, повтори один раз. Снова не вышло → остановись и
   скажи пользователю. Никогда не делай force push.
6. Если изменилось, что скилл умеет или как его ставить, обнови README скилла и строку в
   README репозитория.

## Грабли

- `[ФАКТ]` на каждой строке не нужен. Абзац с одним якорем в конце читается лучше пяти меток.
- Якорь `файл.py:123` устаревает после первой правки. Имя функции живёт дольше.
- Номера разделов не меняются никогда: на них ссылаются комментарии в Jira. Убранный раздел
  оставляет заголовок-заглушку. Исключение - «Активный спринт»: номер постоянный, содержимое
  меняется каждый спринт.
- «Состояние на <дату>» как раздел в `TASKS.md` или промпте - состояние ведётся не там.
- Сжатие без `archive_copy.py` и контрольных вопросов - потеря. Порядок шагов не менять.
- Линтер проверяет форму. Дубли и история в контексте ищутся глазами.
