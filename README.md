# /project-docs - документация как рабочий контекст

Скилл ведёт `docs/` проекта так, чтобы Claude в начале сессии читал две-три записи журнала,
а в конце не терял ничего из сделанного. Он знает раскладку, правила и шесть режимов; сами
тексты проекта живут в проекте.

## Шесть режимов

| Как позвать | Что получишь |
|---|---|
| `/project-docs старт` | **Раскладка.** Новый проект - `CLAUDE.md`, `docs/CONTEXT.md`, `CHANGELOG.md`, `TASKS.md`, `CONVENTIONS.md` по скелетам. Существующая документация - доведение: недостающее, первая запись с «Где мы», метки по таблице, старое в `ARCHIVE/`. |
| `/project-docs итог сессии` | **Конец сессии.** Запись в журнал до 40 строк с блоком «Где мы» по затронутым потокам, закрытые вопросы получили `[ОТВЕТ]`, новые - `[ДООПРОС]`. Пишется сразу, дифф после; подтверждение - только для `CONTEXT.md` и `[ИСПРАВЛЕНО]`. |
| `/project-docs подпроект thread` | **Выделить подпроект.** Папка `docs/projects/thread/` с `CONTEXT.md` и `TASKS.md`, строки в таблицах, запись в журнал. |
| `/project-docs аудит` | **Проверка.** Линтер с уровнями ошибка/предупреждение плюс смысловой чек-лист. Таблица находок с правками. |
| `/project-docs сжатие` | **Документы разрослись.** Действующие решения и грабли - в `CONTEXT.md`, ротация журнала по месяцам, длинные записи в `notes/`, закрытые вопросы свёрнуты на своих номерах, история из `CONTEXT.md` в журнал, процедуры в `howto/`. Копия в `ARCHIVE/` до правки, контрольные вопросы свежему субагенту после. |
| `/project-docs исправить` | **Утверждение оказалось ложным.** `[ИСПРАВЛЕНО <дата>]` на месте в живых файлах, запись в журнал со списком мест. |

Можно словами: «запиши итог сессии», «документы разрослись», «это неверно, поправь в доках».

## Что изменилось по сравнению с `DOC_TEMPLATE.md`

Старый шаблон описывал, где что лежит, и ничего не делал против роста: за два месяца
документация проекта выросла с 4 600 до 20 000 строк. Что добавлено:

- **«Где мы» внутри журнала**, по абзацу на поток в конце каждой записи. Отдельного файла
  состояния нет намеренно: при параллельных сессиях без git он затирается, а разделы
  «Состояние на <дату>» в других файлах линтер считает ошибкой.
- **Бюджеты размера** на каждый файл и запись журнала, и режим «сжатие», который возвращает их
  в норму без потери текста - с архивом и контрольными вопросами.
- **`notes/` и `howto/`** для разборов на дату и рецептов, которые раньше раздували
  `CONTEXT.md`, `CONVENTIONS.md` и журнал.
- **Поводы** - таблица «что случилось - куда писать» и режим «итог сессии», который это делает.
- **Правило чтения** - что читать целиком, что по оглавлению, что поиском.
- **Закрытый набор меток** с расширением только через таблицу в `CONVENTIONS.md`.
- **Номера разделов не меняются**: на них ссылаются комментарии в Jira.
- **Линтер** для формальной части чек-листа.

## Устройство

```
project-docs/
  SKILL.md                  режимы, раскладка, поводы, бюджеты, как читать
  references/
    rules.md                оформление, якоря, метки, что где лежит, формат записи, чек-лист
    compaction.md           сжатие и архив шаг за шагом, контрольные вопросы
    migration.md            доведение существующей документации, таблица переводов меток
    skeletons/              CLAUDE.md, CONTEXT.md, CHANGELOG.md, TASKS.md, CONVENTIONS.md,
                            project_CONTEXT.md, project_TASKS.md, ARCHIVE_README.md
  scripts/
    doc_lint.py             линтер: python3 doc_lint.py <корень> [--summary] [--only CODE]
    archive_copy.py         копия в <архив>/<дата>/ со сверкой sha256 и заготовкой описи; архив - ARCHIVE/,
                            строка `ARCHIVE/` в «Внешних корнях» или --archive-root; повтор за день -
                            суффикс этапа (--suffix) или времени, перезаписи нет
    compact_changelog.py    план и выполнение ротации журнала по месяцам и выжимок длинных записей в notes/;
                            --rules печатает правила и решения из уходящих записей для CONTEXT.md
    verify_moves.py         сверка после переноса: копия из архива против живого файла и файлов --to -
                            ничего не потеряно, перенесено дословно, правки только в --sections
```

Скрипты - только стандартная библиотека Python 3, работают на macOS, Linux и Windows.

## Установка отдельно от репозитория скиллов

Скилл зеркалируется в `https://github.com/MarselBotye/claude-project-docs` (тот же код, та же
история). Поставить только его:

```bash
git clone https://github.com/MarselBotye/claude-project-docs.git ~/claude-project-docs
ln -s ~/claude-project-docs ~/.claude/skills/project-docs
```

Обновляется сам: Шаг 0 скилла делает `git pull --ff-only` в папке, куда ведёт симлинк.

## Как уживается со `sprint-planning`

`sprint-planning` пишет строки `[СОСТОЯНИЕ]` в раздел «Активный спринт» `TASKS.md` и итог
спринта в журнал; `project-docs` их не трогает. Чекпойнты по задачам - «статус», «где мы по
спринту», «итог спринта» - остаются за `sprint-planning`.
